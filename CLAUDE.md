# Battle of the Elements

Кооперативный Tower Defense (1–4 игрока) на Unity `6000.3.12f1` + URP. Фишка — реакции между стихиями башен.
Общение с владельцем на русском; код, коммиты, тексты интерфейса — на английском.

## Где что лежит

| Путь | Что |
|---|---|
| `docs/STATUS.md` | Что готово, что отложено, план. Обновлять в конце крупного шага |
| `docs/DESIGN.md` | Геймдизайн: стихии, реакции, монстры, карты, кампания |
| `docs/CODESTYLE.md` | Правила кода — обязательны |
| `docs/PATTERNS.md` | Готовые решения проекта: как делать виджет, конфиг, пул, экран меню |
| `Assets/Game/Scripts/Core` | Симуляция без `UnityEngine`: всё, что влияет на исход боя |
| `Assets/Game/Scripts/Stage` | Слой Unity: сцены, представления, ввод, HUD, эффекты, сеть |
| `Assets/Game/Scripts/Editor` | Инструменты редактора (`MapForge`) |
| `Assets/Game/Config` | ScriptableObject-конфиги: башни, монстры, уровни, кампания |
| `Assets/Game/UI` | UXML/USS для UI Toolkit |
| `Assets/Scratch` | Временные файлы и скриншоты, в `.gitignore` |

## Цикл разработки

1. Маленький шаг → проверка → коммит. Один коммит — одно логическое изменение, сообщение на английском в повелительном наклонении.
2. Проверки без редактора:
   - `dotnet test tools/CoreTests` — ядро;
   - `dotnet build tools/Stage`, `dotnet build tools/Editor` — компиляция слоя Unity.
3. Если редактор открыт — проверять вживую через Unity CLI (скилл `editor-check`): перекомпиляция, Play mode, клики по UI, скриншоты.
   Если закрыт — batchmode (`Unity.exe -batchmode -projectPath . -executeMethod ... -quit`); нужен вход в Unity Hub.
4. Сцены, префабы и ассеты при открытом редакторе меняются через редактор (`script eval_file`), а не правкой YAML.
   Новые поля конфигов можно заполнять правкой `.asset`, пока редактор закрыт.
5. Изменения, которые редактор сделал сам (материалы VFX, `ProjectSettings/EditorSettings.asset`), в коммиты не включать.

## Правила, о которых легко забыть

- Всё, что влияет на симуляцию, идёт через ядро и приказы (`IOrders`), иначе кооператив рассинхронизируется. Исключение — отладочные кнопки, доступные только в одиночной игре.
- Покадровый код без аллокаций; пулы (`Stock<T>`) вместо `Instantiate`/`Destroy` в бою.
- Числа — в конфигах (`ScriptableObject`), не в коде. Тексты интерфейса — в UXML или конфигах.
- Новые поля конфигов должны иметь осмысленные значения по умолчанию: существующие ассеты получат именно их.
- `PlayerPrefs` меняются и при проверках: после тестов вернуть настройки как было.
- Каждая строка для игрока — через `Lexicon` и с переводом в `Assets/Game/Config/Locales/ru.txt` (см. «Локализация» в `docs/PATTERNS.md`).
