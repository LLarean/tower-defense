# Паттерны проекта

Типовые задачи и то, как они уже решены в коде. Новый код повторяет эти решения, чтобы проект оставался единообразным.

## Точка сборки сцены

Каждая сцена — один `*Scene : MonoBehaviour` (`BattleScene`, `MenuScene`). В `Awake` он создаёт все объекты и связывает их через конструкторы,
в `Update` прокручивает их в фиксированном порядке: ввод → симуляция → представления → HUD.
Если `Awake` разрастается, часть сборки выносится в приватный метод-фабрику (`BattleScene.Callouts`), а не в «менеджер».

## Конфиг → объект ядра

`ScriptableObject` хранит числа и ссылки на ассеты и умеет собрать неизменяемый объект ядра:
`TowerAsset.Spec()`, `BreedAsset.Breed()`, `ChemistryAsset.Chemistry()`. Ядро не знает об ассетах.
Вложенные данные — `[Serializable] struct` с `[SerializeField] private` полями и свойствами только для чтения (`GradeData`, `SquadData`, `LetteringData`).
Таблицы «ключ → значение» — массив структур и линейный поиск в методе (`SpectacleAsset.Color(kind)`): их мало, и это читается лучше словаря.

## Обратная связь из ядра

Ядро сообщает о событиях через интерфейс (`IFeedback`, `IGarrisonFeedback`), а `Feedbacks` раздаёт их нескольким слушателям.
Новый эффект — новый слушатель (`Spectacle` для частиц, `Callouts` для надписей, `Ledger` для экономики), а не новая ветка в старом.

## Виджет HUD

`IWidget.Refresh()` вызывается каждый кадр. Виджет хранит последнее показанное значение (`_shownGold`) и трогает UI только при изменении:
строки не создаются, раскладка не пересчитывается. Элементы находятся по `name` из UXML в конструкторе.

## Экран меню со страницами

Модальное окно — `VisualElement` с дочерними `class="page"`; `Pages` показывает одну страницу по имени.
Кнопки `class="back"` возвращают на главную страницу. Опасные действия оборачиваются в `Prompt.Ask(вопрос, действие)`.
Пример — пауза в `Hud.uxml` и `Pause.cs`.

## Оформление интерфейса

Стиль — гибрид: в бою тёмные читаемые панели, в меню и сюжетных окнах — пергамент.
Общие токены и классы лежат в `Assets/Game/UI/Theme.uss`, каждый USS начинается с `@import url("Theme.uss");`.

- Цвета — только через переменные: `--ink`, `--ink-soft` (текст на пергаменте), `--cream`, `--gold`, `--night`, `--night-line` (боевые панели).
- `.parchment` — окно меню, брифинга, паузы, итога, кодекса (9-slice из `UI/Skin/Parchment.png`).
- `.seal` — бордовая кнопка в окнах на пергаменте; `.seal--quiet` — второстепенная. Главное действие окна — одна `.seal` без `--quiet`.
- `.rune` — шрифт MedievalSharp для заголовков, названий и надписей реакций; основной текст — Ubuntu Medium (задан в `:root`).
- Боевые панели (`.bar`, `.panel`, `.tooltip`, `.hint`) — фон `--night`, рамка `--night-line`, акценты `--gold`.
- Картинки скина — в `Assets/Game/UI/Skin`, иконки башен — рендеры моделей (`editor-check/scripts/tower-icons.cs`) в `Assets/Game/Art/Icons`.

## Локализация

Ключ перевода — сам английский текст. Переводы лежат в `Assets/Game/Config/Locales/<язык>.txt`: строка `english<TAB>перевод`, перевод строки внутри текста — `
`.
Нет перевода — показывается английский, ничего не ломается.

- `Tongue` выбирает язык (сохранённый или системный) и отдаёт `Lexicon`; `Tongue.Dress(root)` в конце сборки сцены переводит все статичные тексты UXML и ставит на корень класс языка (`lang-ru`), который в `Theme.uss` подменяет шрифт заголовков на Kurale — в MedievalSharp нет кириллицы.
- Текст, который код собирает на лету, проходит через `lexicon.Say("Wave {0}/{1}", wave, waves)`: формат-строка и есть ключ.
- Тексты из ассетов (лор, миссии, сложность, башни, монстры) переводятся по их английскому тексту — в коде `lexicon.Say(level.Title)`.
- Новая строка интерфейса = новая пара в `ru.txt`. Проверка: `editor-check/scripts/untranslated.cs` перечисляет непереведённые строки ассетов и UXML.

## Настройка игрока

`Setting` — кнопка-переключатель, которая хранит значение в `PlayerPrefs` под своим ключом и подписывает себя «Title: on/off».
Потребитель получает `Setting` в конструкторе и читает `On`.

## Пулы

`Stock<T>` для префабов (`Take`/`Give`), заранее созданные массивы для UI-элементов (`Captions`).
Вычисляемые строки кэшируются (`Numerals`), чтобы покадровый код не выделял память.

## Межсценовое состояние

Что выбрано в меню (миссия, сложность, состав игроков), переживает загрузку сцены в `Match` на `NetworkManager` (он `DontDestroyOnLoad`).
В кооперативе хост рассылает это гостям тем же сообщением, что и состав игроков. Без меню (сцена запущена из редактора) действуют значения по умолчанию.

## Тесты ядра

Тест — одно поведение, имя описывает его (`DiesWhenSlainDespiteImmunities`). Поле боя собирается через `Field`, события ловит `FakeFeedback`.
Новая механика ядра без теста не принимается.

## Проверка в редакторе

Готовые скрипты для `unity command script eval_file` лежат в `.claude/skills/editor-check/scripts`: расставить башни и начать бой, нажать кнопку UI по имени, вывести состояние боя.
